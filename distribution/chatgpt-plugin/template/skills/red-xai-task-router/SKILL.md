# Red-XAI Bridge

This connection controls only its owner-approved computer. Check the actual paired device rather than assuming access to any other computer or account.

Before computer work, inspect available bridge_status and get_profile tools. Verify the intended device, installed version, emergency stop, approved folders and effective client permissions. Respect ask/deny/always settings, background-only mode, operating-system consent, account MFA and OAuth pairing. A plugin package or public tool schema does not prove authenticated access.

Use the scoped file tools for file work and preserve existing work. Terminal working-directory checks are not a filesystem sandbox. Use the permitted process tools for terminal work; inspect bounded output and confirm completion before claiming success. List, stop or send input only to jobs owned by this client. Never print passwords, tokens, authorization codes, keys or credentials.

Prefer the available Bridge crawler for public website research. Use its start/status/results workflow and respect site, page, depth, robots and private-network restrictions. Do not silently substitute another crawler.

Terminal and crawler work do not require mouse or keyboard control. Do not widen permissions, change profiles, create another connection or borrow another client's credentials to obtain access.

For permitted GUI work, check the shared desktop lease, inspect a fresh screenshot and apply its image-to-screen mapping before supplying physical coordinates. After each GUI sequence and before non-UI work or becoming idle, release only this client's lease with desktop_release when available. Do not close the app or disconnect other clients.

Check installed capabilities before claiming a feature works. Plugin installation does not update the desktop application, activate subscriptions or payment services, establish another device's connection, or prove another operating system passed testing.

If the endpoint rotates, update the existing private plugin through its supported connection flow using the plain verified HTTPS endpoint copied from the owner's Bridge. Preserve its identity, presentation, skills, permissions and OAuth pairing. Portable MCP server entries use only supported transport, URL and header fields: do not add server-level OpenAI extensions, bearer tokens or an unauthenticated fallback. Native Codex uses OAuth discovery by default. A normal client OAuth flow may require the owner to approve pairing again.
